Why Ferry

Your phone, as a drive

A USB stick is storage your Mac can read. An Android phone isn't — it only answers requests, one file at a time. Every other tool works around that with a window you browse through: you copy each file to your Mac before you can open it, then copy it back when you're done.

Ferry makes it a real drive instead. Your apps open and save files on it directly, exactly as they would on a USB stick.

Seamless

It behaves as though you plugged in an external drive. Double-click and the file opens in whatever app you already use.

Play 4K video

Straight off the phone, no copying it over first. Skip to the middle and Ferry handles it.

Edit and save back

⌘S writes to the phone. No second copy to keep track of, no re-upload step.

Copy, move, drag both ways

Rename and delete too. Quick Look, tags and Get Info all behave normally.

SD card, separately

A memory card mounts as its own volume showing its own free space — not merged into one.

Scriptable

cp, rsync, find, grep — it is a mount point, so everything works.

Because Ferry is a real mount point, anything that reads files works with it — rsync, cron, Time Machine exclusions, your editor. It needs no driver and no reboot to do that.

Why the speed differs: MTP, which the others use, asks the phone for one file at a time — slow directory listings and a wait before anything opens. Ferry uses ADB, and adds some very smart optimisations and caching on top of it.

Setup

Two minutes, once

1

Install Ferry

Three lines in Terminal — see Installation. It brings adb along and starts Ferry at login from then on.

2

Turn on developer options — on the phone

Settings → About phone, then tap Build number seven times.

3

Turn on USB debugging

Settings → Developer options → USB debugging. This is how Ferry reads the phone; no app is installed on it.

4

Plug in and tap Allow

Unlock the phone and accept “Allow USB debugging?” — Android asking whether to trust this Mac. It appears in Finder within a second or two.

Installation

Two ways in

Homebrew is the one to pick unless you have a reason not to: it brings adb along and updates Ferry with everything else on your Mac.

With Homebrew Recommended

Three lines, then you are done:

Terminal 
# Point Homebrew at Ferry's tap
brew tap ramanbanka/ferry

# Trust the tap — needed once per Mac
brew trust ramanbanka/ferry

# Installs dependencies, sets Ferry to start at login
brew install --cask ferry

Manually

Install Android Platform Tools (brew install --cask android-platform-tools), take the tarball from Releases, then:

Terminal 
cd ~/Downloads
tar -xzf ferry-*-macos-arm64.tar.gz

# Put it where the shell can find it
sudo install -m 755 ferry-*-macos-arm64/ferry /usr/local/bin/ferry

# Clear the flag macOS puts on browser downloads —
# without this the binary is killed, not just warned about
xattr -d com.apple.quarantine /usr/local/bin/ferry || true

# Enable Ferry to start automatically at every login
ferry enable
FAQ

Questions

Is it really free?

Yes. No paid tier, no trial, and no feature held back. No account, no sign-up, and nothing to register — install it and it works.

Why isn't it open source?

It may be one day; it isn't yet. The binary is free to use either way. If that rules it out for you, OpenMTP is open source and worth a look.

Why do I need a custom tap and brew trust?

Because Ferry is not in Homebrew's own cask repository yet. Anything not in it has to be published as a tap — a third-party source you add yourself — which is what brew tap ramanbanka/ferry does. brew trust is then Homebrew asking whether you are happy for it to run that tap's install steps, which it needs to because installing Ferry registers a background agent rather than just copying a file into place. Both are once per Mac.

Getting into the main repository takes more than working software: Homebrew asks for a project to be at least 30 days old and to show public interest beyond its author. Ferry is newer than that, so the tap is where it lives for now — and once it is accepted, brew install --cask ferry will work on its own.

Is it signed by Apple?

Not yet — that needs a paid Apple Developer account. Homebrew installs work because the cask clears the download flag for you; a browser download needs the xattr line above. Ferry never asks you to turn off Gatekeeper or SIP.

Does anything leave my Mac?

No. Ferry talks to the phone over the cable and serves the files to Finder on your own machine. No account, no cloud, and no telemetry in the app. Homebrew counts installs if you have its analytics switched on, which is between you and Homebrew.

How is it faster than the alternatives?

Two reasons. Most alternatives speak MTP, which asks the phone for one file at a time — that is why directory listings crawl and everything waits. Ferry uses ADB, the channel Android's own developer tools run on, and adds its own optimisations and caching on top. It also does less: copy-based tools move a whole file before you can touch it, while Ferry serves the bytes an app actually asks for, so opening or seeking in a large file does not wait on the rest of it.

Wireless?

Not yet. USB only for now.

Will it drain the battery or slow the phone?

Ferry reads and writes only when something asks it to. Idle, it does nothing but check whether the phone is still attached — and the phone charges while plugged in.

What if I unplug it mid-copy?

That transfer fails and Finder says so. Ferry unmounts the volume and waits; plug the phone back in and it returns on its own. Anything already written stays written.

How do I remove it?

If you installed with Homebrew, run "brew uninstall --cask ferry". It stops the agent and unmounts your phone before removing anything.

If you installed manually, run "ferry disable" first, then delete "/usr/local/bin/ferry".
